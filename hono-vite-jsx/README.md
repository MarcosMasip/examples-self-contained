# Hono + Vite + JSX (Self‑contained)

This example pairs Hono with Vite and `hono/jsx/dom` for a browser‑rendered JSX app backed by a tiny Hono API.

## Quickstart (one command)

From the repo root:

```bash
npm -w hono-vite-jsx run dev
```

Open http://localhost:5173/

What you’ll see in the terminal (expected):
- A Vite banner with “Local: http://localhost:5173/”
- You might see a warning like “Could not auto-determine entry point… Skipping dependency pre-bundling.” — this is harmless for this example.

On the page you can:
- Click “You clicked me …” to test client‑side state with `useState`
- Click “Get Server Time” to call the Hono route `/api/clock` and see the response printed

## How it works

- `src/index.tsx` defines a Hono app with:
	- GET `/` → serves the HTML shell with `<script type="module">` pointing to the client entry
	- GET `/api/clock` → returns the current time JSON
- `src/client.tsx` renders the UI with `hono/jsx/dom`, uses `hc()` to call the server route.
- `vite.config.ts` wires both the dev server and the build for client + server entries using `@hono/vite-dev-server` and `@hono/vite-build`.

Dev vs Prod client script:
- In dev, the HTML includes `<script type="module" src="/src/client.tsx">` served by Vite directly.
- In prod (after build), it includes `/static/client.js` generated by the client build step.

## Build

```bash
npm -w hono-vite-jsx run build
```

This generates the client file at `dist/static/client.js` and a server bundle. You can adapt runtime targets by changing imports in `vite.config.ts`.

Notes
- No external services or environment variables are required for local dev — it’s fully self‑contained.
- The `test` script is a no‑op in this example and exists only so workspace test runs complete without errors.
